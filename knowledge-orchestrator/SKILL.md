# 知识库主控

## 执行范围与复用

先区分小修、已有候选入库、增量资料或批量建库，走最短必要路线；本会话未变的规则与完整有效的阶段结果复用。仅格式/入口小修不重跑资料提取。具体复用条件、批量工具和失败边界见[按范围执行与结果复用](references/按范围执行与结果复用.md)，需要缓存或正式写入时读取。图片文字、完整模板、动态0号和Markdown结构质量要求不降低。

## 职责与默认结果

负责确定任务、选择阶段、比较旧库、统一日志和最终验收；具体转换、拆解和写作交给 `knowledge-processor`。不把处理规则全部复制进主控，也不默认开多个 agent。

默认产出可直接使用的方法、模板、案例和检查工具。来源与运行信息放目标库 `依赖/`，不加知识正文来源尾段。正式库必须有按任务找文件的 `00_先看这里.md`，不能只列文件名。

## 自动创建与复用目录

首次未确定存放位置时先弹窗或对话询问盘符/文件夹，确定实际根路径后再创建；不得硬编码盘符或默认当前工作目录。首次使用在总知识库根目录创建一套公共结构和根0号；后续复用同一根目录填充。正文主题不是子知识库，不在主题内重复初始化五类目录。


正式建库或交付前读取[目录结构与自动归档](references/目录结构与自动归档.md)。缺少目录就创建，存在就直接复用并按计划填充。正文按主题分组，每组有0号；附件按来源分组；管理与来源分开；每批在依赖区生成一份Markdown说明。

## 开始任务

1. 从当前请求及既有配置确定输入、实际目标库与本次范围。仅看差异/试稿/只读任务不自动变成正式入库；目标库不明时先读取和规划，再问必要的问题。
2. 首次读取[任务交接与恢复](references/任务交接与恢复.md)和[统一日志与交付](references/统一日志与交付.md)。已有任务复用 task_id；用户已授权范围持续有效。
3. 每批集中盘点、hash和检索。输入与目标库重叠时，排除本任务生成的日志、转换稿、候选与备份，避免将自己的输出再次入库；不要因此排除用户原有知识。先快速检查同批与历史原件；相同字节仅在处理完整且当前产物仍有效时跳过。部分失败、遗漏或要求按新标准重做则继续。

## 选择最短可完成路线

| 请求 | 路线 |
|---|---|
| 新建知识库 | 快查 → convert → extract → 同批去重/归并 → organize → 验收 |
| 旧库增量资料 | 快查 → 必要的convert/extract → classify → organize → 验收 |
| 只看差异/重复 | 已有可读材料 → classify；交判断，不发布 |
| 只转换/只拆解 | 交处理器对应阶段；只执行该阶段 |
| 只整理既有提取材料 | 核对材料及落点 → organize，不重新转换 |
| 继续未完成任务 | 验证已有输入/输出hash → 只恢复缺失、失败或失效的阶段 |

空库不扫描不存在的旧知识；禁止在拆解前仅凭标题给所有知识定性。主控读取必要来源与候选旧页，必要时扩展相关检索，但不每份上传都从头扫整个大库。

## 调度处理器

默认阶段与工人登记见[能力注册表](references/capabilities.json)。使用宿主真实可用的 Skill 调用方式；没有调用接口时，读取同级或已发现的 `knowledge-processor/SKILL.md`，在当前 agent 内按它的阶段执行。不能捏造“已召唤”或“子agent完成”。

向处理器传 `task_id`、明确阶段、输入产物路径与hash、目标库/工作区、已有授权及本阶段输出要求。处理器返回完整/部分/失败、产物位置、未解项和建议，不自动执行后续阶段。

交接文件只存摘要与文件定位，不反复塞原文。已有内容未变就复用；同批材料集中处理，管理记录集中保存。

## classify：重复与更新判断

仅进入此阶段时读取[重复文件处理与旧知识更新](references/03_重复文件处理与旧知识更新.md)。

- 按知识条目对照旧正文及实际来源，不给整份上传只贴一个动作。
- 分别判断增加、补充原文、补充成篇、修改、重复跳过、仅更新依赖、待确认。
- 同名不同文件不覆盖；同主题不等于重复；新版本不自动否定旧版；不同条件先分开解释。
- 修改需要可复核依据；同条件冲突仍未能裁决的，保留候选和证据，不抢写确定结论。
- 输出精确落点、差异、理由、所需资源/入口/依赖变化和旧目标预期hash，交 organize 执行。比较本身不写正式知识。

## 验收、日志与恢复

验收图片资料时，检查文字型图片是否已转成可搜索、可复制的正文，并核对条目/模板子项覆盖。只嵌入原图或只读HTML文字层不得算完整入库；示意图可保留，识别缺失必须列明。重复判断也要覆盖图片中提取的知识。


候选、已写入和已核验分开记录。按日志规范记录真实阶段边界、跳过、冲突和失败；只有正文、资源、导航、依赖及必要日志一致后才记 committed。

检查0号能回答“我要做什么、看哪个文件、先后怎么用”。检查完整提示词、案例、字段和限制，没有因为合并丢失旧知识。程序路径/结构校验不能替代语义审校。

只报告实际读取范围和变更；未运行模型、OCR或独立审校时如实说明。不能为满足状态表而虚构成功、审批或来源。

## 添加新功能

需要扩展时才读[扩展接入规则](references/扩展接入规则.md)。通过登记触发条件、输入、输出、作用阶段和写入权限接入，不重写主流程；未安装或未验证的能力不得自动执行。不得因请求上传材料就自动联网研究或启用无关扩展。


Markdown交付需检查真实渲染结构：表格的分隔行和列数、标题层级、列表边界与完整模板代码块。只通过文件hash或链接检查不能算格式验收通过。

0号随知识与资料变化动态维护，纳入同批验收和日志；根及五类公共目录各有0号。正文0号严格只概述/导航当前层直属内容，不能递归展开子层文件；其他目录按用途组织。细则见目录结构与自动归档。

格式验收须把源材料覆盖映射到成品：案例、完整提示词块及工具/备注归属一致；指定修复后对同生成路径稿件轻量排查。处理器带markdown_preflight.py，数量预期按实际提取覆盖提供，工具结果不替代语义或渲染检查。
