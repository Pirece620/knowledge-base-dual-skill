# 图片文字提取与图文交付

## 先按用途判断图片

|图片类型|处理方式|
|---|---|
|文字型：提示词卡、步骤清单、参数表、文本截图|提取成可搜索、可复制、可编辑的Markdown正文；原图只作核对，不用截图替代正文|
|示意型：构图、走位、动作轨迹、结构关系、效果对照|保留图片并解释关系、方向、动作与适用条件|
|图文混合|提取重要文字/表格/提示词，保留有解释作用的图；两者建立对应|
|装饰、广告、二维码|不作为知识内容；按任务需要登记或跳过|

只读到HTML文字层不等于读完文章；正文很短而有大量图片时，必须检查图片是否承载核心知识。

## 提取与核对

1. 使用宿主实际可用的视觉识别或本地OCR；不得声称自带OCR，也不自动上传私密图片到外部服务。
2. 保留图中标题层级、条目编号、表格行列、完整提示词与占位符，恢复正确阅读顺序，合并排版换行。
3. 对照原图检查OCR错字、漏行、跨栏串行、箭头方向、正负号、单位、参考图标签和条件。不能只凭OCR置信分数判完整。
4. 列表/模板按组核对数量、连续编号、每组子项与跨页接续。标题数量与实际不符时记录差异，以实际内容为准；数量核验不替代语义核验。
5. 原文有错误时区分“识别误差”和“来源本身错误”：前者修正文字；后者保留原件，在整理稿说明必要修正，不把整理版冒充逐字原文。
6. 重要文字看不清时，明确图号及缺失条目；可完成部分继续。关键模板未提取完整则标部分完成，不将原图存在记为全部已提取。

## 正式整理与查重

提取的文字参与知识级重复、补充和冲突比较，不能只比较HTML正文或图片hash。相同图片可以复用提取结果；字节不同的重编码图片仍可能文字相同。不同版式、同一模板的概览和详解应比较完整度后归并，独有条件/例子保留。

知识正文优先给可用的文字方法、表格和代码块，示意图放在解释旁边。纯文字原图可给核对链接或折叠展示，不能写“可直接复制”却仅放图片。不得用“图卡完整保留”替代完整提示词、步骤和字段提取。原图、文字、图号映射与读取限制保存在依赖/管理记录，不在正文堆来源尾段。

交付前确认：不打开图片仍可搜索和使用其中的文字型知识；必要的示意关系仍能看懂；完整模板未变成三句摘要；未识别部分与已完成部分分别记录。
