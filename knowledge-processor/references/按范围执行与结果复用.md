# 按范围执行与结果复用

## 先选最短路线

|任务|执行|不重复做|
|---|---|---|
|小修：格式、入口、错字或少量指定位置|读取目标及必要依据→修改草稿→检查受影响结构/链接→条件提交|不重新抽取所有原件，不扫描全库，不重写无关0号|
|已有判断后的入库|核验已有输入、覆盖、候选与目标版本→直接整理/提交|不从HTML重新转换，不把classified当已发布|
|增量资料|批量登记→复用有效转换/提取→只比较相关知识→提交|不每篇资料重复扫描相同目录|
|新建批量知识|一次盘点→集中转换/识图→提取/判断→成稿预检→一次批量交付|不先粗略入库再补模板或OCR|

本会话已读取且未变化的规则不重复整篇加载；首次执行只读当前阶段和风险需要的资料。修单个表格不加载无关全部加工规则。不得以“小修”绕过实际所需来源比较、图片识别或格式检查。

## 阶段结果是可复用产物

转换稿、图像识别文本、资源映射、完整知识材料、覆盖表与判断清单分别保留路径和hash。后续请求“入库”继续同一任务链，先核验产物再执行剩余阶段，不重新从原件总结一遍。完整案例与提示词应在提取阶段保留，不到发布后才补。

复用条件：实际输入相同、当前有效规则签名相同、提取工具/配置签名相同、产物存在且hash匹配、上次complete且coverage_complete为true。partial/failed、重要图未读、条目缺失、旧标准要求重做、输入/规则改变、缓存产物被编辑均不能直接复用。签名由本次实际有效配置/规则内容生成，不拿固定字符串长期冒充未变化。纯排版修改只让相关成品失效，不要求重跑无关OCR。

图片原字节/已识别结果优先复用；重编码或裁剪只能形成相似候选，不能直接跳过识别。OCR先批量运行，再集中核对低把握、漏行、数量/跨页和重要参数；语义、模板完整性和关键动作不能仅按置信度抽样放行。

## 公共工具

随包`scripts/knowledge_batch.py`与`knowledge_io.py`放在同目录，只使用Python标准库；不捆绑OCR、Markdown解析器或模型。识别、语义审校、目录归属、0号内容和Markdown渲染仍由Agent及宿主实际工具完成。不要为相同任务临时重写提交/备份脚本。

### 缓存检查

```text
python scripts/knowledge_batch.py cache-check --work WORK --request request.json --cache cache.json
```

request包含stage、policy_sig、producer_sig和inputs数组（每项为WORK内相对path、sha256）。cache保留这四项及status=complete、coverage_complete=true、artifacts数组（相对path、sha256）。工具核验真实文件，返回reusable与失效原因；不自动读语义、不自动生成缓存，也不把true视为本次语义验收已通过。缓存记录由执行阶段的Agent基于真实完成状态生成。

### 批量条件提交

```text
python scripts/knowledge_batch.py commit --root LIBRARY --work WORK --plan plan.json
```

plan包含task_id、authority_ref、reason、protected_prefixes数组及files数组。每个文件项：path为库内目标相对路径，candidate为WORK内候选相对路径，candidate_sha256为候选实际hash，before_sha256为目标预期hash（新增必须null）。同一计划包含正文、受影响0号和批次依赖；机器日志由工具单独记录。authority_ref引用已有真实授权，不要求用户再确认普通步骤。

工具只新增/修改，不删除/迁移。不允许计划覆盖工具自己的日志、提交记录和历史目录；新文件独占创建，旧文件加锁重查版本，仅备份实际被改的旧文件，写后校验，一批只写必要事件。未变化文件不重写。相同task_id、相同计划且已提交产物仍匹配时复用结果；不同计划或外部修改拒绝覆盖。

多文件不是全库原子事务。中断或部分失败时保留管理/更新计划/<task_id>/批处理状态.json与管理/历史版本快照，停止盲目重跑；Agent核对实际文件后形成恢复操作。工具不自动回滚、自动推断授权或替代内容预检。

## 合并校验与记录

写前集中检查本批发生变化的表格、模板、图片文字覆盖、链接与0号；写后只核对受影响产物。复用相关旧知识阅读结果，不因增加一个文件重查整个库。完整图文审校与版本冲突检查保留，不能为了加速降为只查文件存在。

小任务用一份计划、必要历史快照及批次记录；不要为每条内部步骤创建重复清单。Skill本身未变时不重打Skill包；用户要求更新Skill时在本轮结束集中打包一次，保留使用说明和更新日志。

记录各实际执行阶段的起止/耗时（如盘点、转换/OCR、判断、写作、预检、提交），复用阶段记reused与依据。只记录实测，不用工具的IO耗时冒充模型总耗时。优化验证比较同一批输入、相同质量要求、读取覆盖和返工数，不先承诺加速比例。
