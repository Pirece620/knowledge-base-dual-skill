# 知识拆解与提取

涉及图片、扫描页或文字截图时，读取[图片文字提取与图文交付](图片文字提取与图文交付.md)：文字型图片必须转为可用文字，图文混合分别处理；原图保留不能代替提取完成。


## 一、用途与输入输出

输入：可读取的转换稿、必要原件/图片、已确认任务范围及转换缺失记录。

输出：发现的知识主题、每个主题的完整材料、原文位置与覆盖处置、建议主题边界。此时不必写成正式知识文件，也不对旧库直接增删改。

“拆”是理解和归属，不是机械按段落切碎，更不是把每篇资料压成摘要。

## 二、通读并建立内容覆盖

先了解资料全貌，再决定如何拆分。记录以下有知识作用的内容：

- 概念、定义、分类、判断依据。
- 方法、步骤、前置条件、输入与输出。
- 参数、范围、单位、字段含义和填写要求。
- 适用场景、限制、例外、风险和失败条件。
- 案例、反例、对照、推导和操作演示。
- 完整提示词、代码、公式、表格和可复制模板。
- 图片、图注以及图与正文的对应关系。
- 错误表现、原因、修正方法和验收标准。

覆盖单元按实际内容划分：一个完整步骤、一条规则、一张表、一个案例、一套提示词或一张图均可成为单元；不要求机械地把每句话单独编号。

若资料量大，按文件或章节分批处理，保留待处理清单。最终必须区分“全部完成”“部分完成”和“无法读取”，不能因为生成了几篇笔记就宣布全部整理结束。

## 三、发现主题并确定边界

主题来自实际内容。用户举的例子和资料原有标题都只是线索，不能当作可提取主题的上限。

按三个问题决定拆分：

1. 这部分内容独立解决什么问题？
2. 它与相邻内容是否属于同一个任务、概念或判断过程？
3. 拆开后能否独立理解，合在一起是否仍清晰？

| 情况 | 处理方式 |
|---|---|
| 一篇材料包含多个可独立使用的主题 | 拆成多份知识文件 |
| 多篇材料都在解释同一个方法 | 对照后合成主题文件，保留各自适用条件和来源 |
| 一个案例用于解释某条规则 | 放在规则旁边；较长的完整案例可另存文件并明确引用 |
| 某段依赖前后步骤才能理解 | 保持步骤连贯，不为增加文件数而拆散 |
| 一个主题短小但信息完整 | 可作为同一手册中的独立章节，不强行单独成页 |
| 一套流程含多个长模板 | 总流程说明与模板包分开，标明每个模板的使用顺序 |

示例：一篇“AI 写短剧完整工作流”可以整理为一个总流程文件，加一个完整提示词模板包；也可以按选题、大纲、逐集编写、钩子优化、自查拆分，但必须保留五个阶段的输入输出关系。

不规定每个来源最多生成几篇知识文件，也不要求每篇来源必须生成一篇新文件。只要求有用知识得到明确归属，重复内容得到合理处理。

## 四、逐项提取完整知识材料

每个主题至少检查以下内容是否在来源中存在；存在则提取，不存在则不编造：

| 提取项 | 要保留的内容 |
|---|---|
| 作用 | 解决什么问题，预期得到什么结果 |
| 条件 | 适用对象、前置要求、输入和使用环境 |
| 方法 | 动作顺序、决策分支、关键判断和原因 |
| 细节 | 参数、单位、字段、约束强度、例外与限制 |
| 资产 | 完整模板、提示词、代码、公式、表格、图示 |
| 示例 | 具体输入、处理过程、输出和示例说明 |
| 验收 | 正确表现、失败表现、检查与修正方法 |

特别要求：

- 原文提供五套提示词，就保留五套完整提示词及其使用条件，不能只写“五阶段工作流”。
- 原文提供分镜表，就保留实际字段、字段解释和填写示例，不能只列出几个字段名称。
- 原文提供操作案例，就保留关键输入、操作和结果，不能压成“作者举了一个案例”。
- 原文提供检查清单，就保留具体检查项和判定条件，不能改成“注意检查连续性”。
- 原文提供数字、阈值或时长，就保留单位、对象、条件和来源属性，不能把经验建议升级成硬性规则。

提取目标是知识保真，不要求逐字复制所有正文；可合并重复解释、调整顺序、改成表格或通俗表达，但不能删掉影响使用的条件和细节。

## 五、同批资料的重复与冲突先保留线索

同一个方法被多份资料讲述时，可以归到同一主题下，保留各自新增的条件、细节和来源位置。来自同一原始文章的转载不自动增加独立证据。

不同版本、对象、任务或条件的规则先分开记录；不因措辞相近就归成完全相同，不因新旧说法不同就判断旧库错误。

本步可以给出“可能重复、可能补充、可能冲突”的线索。与旧库比较后的正式增加/补充/修改决定，交给 `03_重复文件处理与旧知识更新`（由主控按阶段路由）。

## 六、轻量交接表

| 主题 | 解决的问题/知识作用 | 已提取材料 | 原文位置 | 边界与缺失 | 建议去向 |
|---|---|---|---|---|---|
| 实际主题名 | 方法/概念/模板/案例等 | 步骤、条件、完整资产等 | 文件及章节/页码/转换稿行号 | 完整/部分/待确认 | 新主题候选/已有主题线索 |

必要时附内容覆盖表：原位置、内容单元、保留/重组/合并/排除/未解决、目标主题和原因。记录可集中在一份工作文件，不强求每个段落一份JSON。

## 七、交接前检查

- 所有明显重要主题都有归属，不把用户举例当作主题数量上限。
- 模板、案例、字段、参数、限制和图片信息得到保留或明确标缺。
- 核心材料有实际来源，不凭模型常识填空。
- 没有把“正文已可搜索”当作无需提取实用方法的理由。
- 未解决的重要内容列明，不能宣称全部提取完成。

先交03判断，再进入04正式整理；空库也做本批主题去重和归并，但不需要扫描不存在的旧库。
