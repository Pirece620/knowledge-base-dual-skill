# 知识整理与成品交付

涉及图片、扫描页或文字截图时，读取[图片文字提取与图文交付](图片文字提取与图文交付.md)：文字型图片必须转为可用文字，图文混合分别处理；原图保留不能代替提取完成。


## 一、用途与输入输出

输入：02的主题与完整知识材料、03确定的增加/补充/修改/跳过/待确认结果，以及当前旧正文和实际授权范围。

输出：条理清晰的正式知识、完整模板/案例、必要附件、好用的0号入口、独立依赖记录和真实更新日志。

本步负责把材料写成读者能用的知识，不重复转换和从头提取，也不绕开03另行决定覆盖旧库。

## 二、先明确成品应该解决什么问题

整理后的每份知识文件，都应能回答一个明确的问题，例如：

- 如何填写分镜表？
- 如何判断前后镜头是否连续？
- 如何把心理描写改成可见动作？
- 如何分步骤使用一套剧本提示词？

正文围绕这些问题组织，让读者知道：什么时候用、需要什么、具体怎么做、结果长什么样、怎样判断做对了，以及哪些情况下不能直接照用。

成品可以是方法手册、概念说明、规则说明、对比选型、操作流程、案例解析、提示词模板、表格模板、排错指南或自检清单。按知识作用选择结构，不强迫所有内容套同一种模板。

来源摘要可以作为资料管理层保留，但不能用它替代应当交付的方法、案例或模板。原始文件留在附件中，也不能算已经完成知识提取。

## 三、按判断结果安排正文

- **增加**：围绕独立主题组织新文件，不按来源数量机械建页。
- **补充原文**：把新步骤、条件或短例插入相关章节，保留仍然正确的旧知识，必要时重排受影响小节。
- **补充成篇**：完整模板、长案例或独立方法可另写配套文件，说明其在任务中的位置。
- **修改**：依据已确认差异修正错误和受影响内容，不能趁机压缩或重写无关旧文。
- **重复或待确认**：不写成新的确定知识正文；记录复用、跳过或待确认原因。

具体判断标准和写入约束见 `03_重复文件处理与旧知识更新`（由主控按阶段路由）。

## 四、正文怎么组织

将来源的叙述顺序转换成使用者需要的顺序：先说明问题与条件，再讲方法，随后给示例、模板和检查。

写作要求：

- 直接讲知识与方法，减少“文章指出”“作者介绍了”“本文认为”等转述句。
- 用具体动作替换空话。例如“逐项比较上一镜结束状态与当前镜开始状态”，比“注意连续性”更可执行。
- 术语首次出现时解释到足够使用，不堆名词。
- 每个步骤写清做什么、依据什么判断、下一步做什么。
- 比较关系、字段说明、状态判断优先用表格；连续操作按顺序写。
- 案例放在对应方法附近，让读者能看懂方法如何落地。
- 所有依赖外部条件的规则都保留条件，不用统一绝对化措辞。

来源可以被改写为清楚的操作说明；证据不足时在对应位置标出“来源建议”“示例值”或“待核验”。不要用大段泛化免责声明淹没方法正文。

## 五、图片、表格与可复制资源

图片处理：

1. 区分知识图示与装饰、广告、二维码。含有信息的图不能只因难处理而跳过。
2. 保存可获取的原图，使用相对路径引用，避免只依赖可能失效的外链。
3. 为图片写清图名、它解释的问题和对应步骤；图中的重要信息尽可能转成文字或表格。
4. 能实际读取图片才写图意。无法确认的标签、数值和 OCR 内容标为待确认，不能猜。
5. 需要重绘时标为整理示意，并核对关系、方向、标注和参数是否一致。

提示词、代码和模板处理：

- 原样可复制版本保留完整边界、占位符和字段顺序。
- 解释写在代码块外，避免读者复制时混入说明。
- 如需改进，另列“整理版”，说明修改了什么，不能默默改写后仍称原版。
- 输出模板与填好示例配套；来源没有示例时，可制作明确标注为“整理示例”的演示，不把它当真实案例或验证结果。

## 六、命名、编号、归类与导航

文件名用清楚的中文知识主题，必要时带适用场景，例如：

- `小说心理描写转画面的处理方法.md`
- `分镜脚本标准字段与填写示例.md`
- `上下镜头连续性检查.md`
- `微短剧编写提示词模板包.md`

按知识用途和内容组织目录。用户已有分类时优先沿用，不先强制建立一套新分类体系。

存在真实先后顺序时可使用 `00_使用说明`、`01_…`；没有先后关系时，可按用户约定的分类与稳定编号安排，不伪造流程依赖。文件多或存在配套关系时，提供简洁入口，说明先读什么、做事时查什么、最后用什么检查。

双链用于解释前置知识、下一步骤或配套资源。链接必须说明关系，不能为了图谱数量添加无意义链接；读者不应反复跳转才能读到一条方法的必要条件。

本套规范按 `00_` 至 `04_` 排列。用户要求编号的知识成品也使用前置编号，编号反映真实使用顺序；不要为了加入一篇内容就重排全部既有文件。改变旧文件名要先评估引用影响并遵循03的计划授权。

### 0号入口必须单独审校

每个正式知识库都应有 `00_先看这里.md`，或沿用用户已有的同等入口。入口以使用者任务为中心，至少提供：

- 库的用途、适合谁和能解决的问题。
- “我要做什么 → 看哪份文件”的可点击任务表。
- 必要阅读顺序、配套模板和检查文件的位置。
- 知识、附件、依赖等目录的使用说明。
- 影响使用的缺失范围或待确认事项。

入口不堆来源hash、运行日志或只列文件名。新建、补充和合并改变导航时，同步维护相关条目，并验证每个链接真实存在。已有入口不需要更新时，不为形式完整重写它。

## 七、按知识作用选择正文结构

### 结构 A：方法与流程

```markdown
# 主题名称

## 用途与适用条件
解决的问题、需要的输入、适用环境和前置条件。

## 操作方法
按实际顺序写步骤、判断依据和分支。

## 完整示例
输入 → 处理过程 → 输出；解释关键变化。

## 常见问题与检查
错误表现、原因、修正方法和通过条件。

## 适用限制
只写会影响实际使用的前提、版本条件及限制。来源定位与验证记录写入根目录依赖区。
```

### 结构 B：模板与提示词

```markdown
# 模板包名称

## 使用顺序
本模板用在哪一步，前一步交付什么，下一步如何接续。

## 填写说明
字段含义、必填项、占位符、限制和替换方式。

## 完整模板
保留可直接复制的完整文本或表格。

## 填好示例
真实来源示例，或明确标注的整理示例。

## 提交前检查
可逐项判断的检查清单。

## 使用限制
说明模板的实际使用前提；出处、整理修改范围与验证记录写入根目录依赖区。
```

### 结构 C：检查与排错

```markdown
# 检查主题

## 检查对象与前提
检查什么，需要哪些文本、画面或配置。

## 检查顺序与判定规则
先后顺序、正常/异常/信息不足的判断依据。

## 检查表
对象 | 检查问题 | 证据 | 结论 | 修正建议

## 问题示例与修正
错误表现 → 问题所在 → 修正 → 复检。

## 报告模板
可复制填写的结论和待解决事项。

## 判定限制
说明哪些缺失信息会影响判定；出处和本次整理记录写入根目录依赖区。
```

概念、分类、对比和原理内容可采用“定义 → 区别 → 适用情形 → 例子 → 局限”等结构，不为了凑齐栏目编造操作步骤。上述标题可按主题调整，验收关注信息是否齐全。

## 八、来源与管理信息独立存放

知识正文优先展示读者要用的内容。来源、采集日期、文件指纹、处理批次和审校记录按作用分开保存：

- **知识正文不放“来源”“来源与边界”等管理性尾段。** 在知识库根目录建立 `依赖/`，或建立单个 `依赖说明.md`，统一保存出处、原文定位、版本、整理修改范围、验证状态和未核实声明。
- 依赖记录必须按知识文件名建立对应关系，能查到每个主题使用了哪些来源及具体位置；来源多时可一篇知识配一份依赖说明。
- 实际影响方法使用的前置条件、参数限制、错误提醒和不确定输入仍写在正文相关位置；不能因分离来源说明而将有限条件的建议写成普遍事实。
- 依赖记录中，长来源文件提供章节、页码或原文位置，不能只给一个无法定位的大文件名。
- 完整 hash、运行日志、来源映射和处理状态可留在独立管理记录中。
- 只有宿主确实需要时才添加对应 frontmatter，不把一整屏管理字段当作知识正文。

来源不明确或没有经过实测的情况在依赖记录中如实说明，不在每篇知识正文重复堆放通用声明。根目录入口指向依赖区即可，不要求每篇正文附带来源链接。

## 九、怎样判断已经整理到可用

### 例 1：从短剧文章到可用提示词文件

来源：包含选题、大纲、单集剧本、钩子优化、自查五个阶段及完整提示词的教程。

不足的产物：只剩三条“原文要点”和几个相关链接；读者知道有五个阶段，却拿不到五套提示词。

应交付的内容：

1. 总流程：每个阶段需要什么输入、完成什么任务、交付给谁。
2. 五套完整提示词：保留输入占位、要求、输出字段及阶段关系。
3. 使用说明：哪些信息要填入，上一阶段哪部分结果要带到下一阶段。
4. 检查项：输入是否齐全、输出是否满足本阶段要求、是否遗漏前后衔接。
5. 适用边界：原文时长、字数等为特定建议，不冒充所有平台或所有剧本的统一标准。

成品可命名为 `微短剧编写流程与阶段交付.md`、`微短剧编写提示词模板包.md`，按篇幅决定是否分开。

### 例 2：从连续性说明到检查手册

来源：关于人物、门窗、伤情和道具在前后镜头中保持一致的说明。

不足的产物：“拍摄时注意人物与道具连续性。”

可用的正文应明确：

- 检查单位：上一镜结束状态与当前镜开始状态；必要时再看下一镜。
- 前置判断：是否同场景、连续时间，是否发生转场或时间跳跃。
- 检查对象：位置、朝向、姿态、接触关系、门窗、衣物、伤情和持物。
- 判定：一致、合理变化、矛盾、待确认；变化应有动作或事件依据。
- 示例：上一镜受伤，下一镜无处理而无伤，应指出具体冲突。
- 表格：上一镜状态、当前镜状态、证据、结论和修正建议。

这些结构取自手工分镜库的表达方式。实际提取其他主题时，只保留其来源支持的规则；新增的检查设计要标明为整理建议。

## 十、对照材料审校

先核对内容，再检查排版与链接。不能只凭字数、文件数、属性完整或链接无错判断整理成功。

审校分为四类：

1. **主题覆盖**：来源中重要主题有没有漏掉，是否有内容无归属？
2. **知识保真**：步骤、条件、数字、限制、例外、模板与案例是否准确保留？
3. **结构清晰**：文件边界是否合理，重复是否归并，冲突是否解释，标题是否能帮助检索？
4. **实际可用**：读者能否照着完成一次任务，模板能否直接复制，检查项能否给出明确结论？

关键内容没有读取、重要主题未提取或核心模板残缺时，标为部分完成，不能进入“全部完成”状态。

## 十一、交付前验收

- [ ] 已说明实际阅读范围，未读取内容明确列出。
- [ ] 重要主题均有目标位置，没有只处理用户举例的几个主题。
- [ ] 方法的输入、步骤、判断和输出可理解、可执行。
- [ ] 来源中的关键参数、条件、限制和例外没有因压缩而消失。
- [ ] 完整模板、提示词、代码和表格得到保留，能直接复制。
- [ ] 案例保留必要输入、过程和结果，读者能看懂用途。
- [ ] 有知识作用的图片已保存或明确报告无法读取，图文能对应。
- [ ] 多来源重复已归并，冲突和适用条件没有被抹平。
- [ ] 原文观点、整理推断、补充建议和待确认内容可以区分。
- [ ] 文件命名、章节顺序、导航与必要链接清楚。
- [ ] 每份知识有对应依赖记录，来源能定位；正文没有来源、整理过程和通用验证声明等管理性尾段。
- [ ] 没有将结构校验通过、字数增加或文件数量当作内容质量证明。

只要关键项未满足，就应继续修订或报告部分完成。

- [ ] 03中每个条目的实际处理结果已经核对，增加/补充/修改没有混淆。
- [ ] 0号入口能帮助使用者选文件、理解顺序，并且链接有效。
- [ ] 写入前检查目标未被外部改变，旧版可恢复，实际提交在授权范围内。
- [ ] 日志与正文、附件、入口和依赖记录一致，失败或部分提交未冒充完成。

## 十二、提交与恢复

在具备实际安全写入能力时，按03执行计划和写后验证，统一记录到目标库 `管理/日志/`。不能安全提交时交付候选和差异，不宣称已更新。

发生外部编辑或版本变化，重做受影响比较；中断后先对照日志与实际文件恢复，不重新覆盖已经变化的用户内容。


## Markdown结构验收

不能把HTML get_text、OCR逐行文本或中间转换稿直接当最终Markdown。识别表格、标题、列表与模板边界后重建结构。

- 表格必须有表头和紧随其后的分隔行（如|---|---|）；逐行列数一致，单元格内竖线转义，长单元格不要用裸换行拆开。不能仅因文本含竖线就认定已成表。
- 完整可复制提示词使用带语言标记的围栏代码块，说明放块外；[任务]、占位符、编号和#等保留在模板块内，避免被编辑器误解释。模板之间建立真实Markdown标题和空行，不能让上一列表吞入下一模板。
- 转换造成P##等标签断裂时对照原文重接，不能静默丢字段、补剧情或改参数。保真修复与内容纠错分开记录。
- 交付前使用可用Markdown解析器检查预期表格数、表头/列数、标题层级及代码块数量/边界；抽查渲染结果，不能只查hash和链接。没有解析/预览工具时做等价语法检查，并如实说明未预览。
- 表格原始材料本身缺分隔行、代码块未闭合、模板字段裸露或内容被当列表时，应先修复再交付。正常阅读版与逐字模板区分开；格式修复后核对完整条目和模板正文没有丢失。


## 表格型提示词的案例关联与预检

HTML表格先按tr/td/th及rowspan/colspan还原行列，再提取各字段。至少保留每个知识单元与其提示词、图像、工具/参数和备注之间的对应；get_text或OCR逐行文本只是中间材料，不能直接跨列串入成品。长提示词适合按案例独立分节，提示词在text代码块、工具与备注在块外；短对照数据可继续用表格，不强制所有表格改成案例。

提取覆盖应给出实际单元数与字段归属，交付按该覆盖核对标题、完整复制块与标签对应。多时间段可能属于同一提示词，不按行数拆例；备注不能并入操作指令。已知数量只作为本次预期，不把实例数字写成通用标准。

随包scripts/markdown_preflight.py提供无额外依赖的轻量预检：--file FILE，可按实际覆盖加--expect-fences N和--expect-cases N。它检查缺表格分隔行、未闭合围栏及预期数量，并提示裸模板字段/工具孤行。warnings必须结合语境处理；passed不代表已做渲染、语义核验或表格列关联审校。标题数字、通过计数或空代码块不能替代内容完整性。

指定格式问题修复后，对本批同模板生成或同提取路径的相关文件做一次轻量检查，发现线索才扩大。小修不重跑全库或OCR。正文整体是否完整、每块是否与原字段对应仍需Agent核对。
